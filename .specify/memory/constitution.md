# DFP Connect 헌장 (Constitution)

## 핵심 원칙 (Core Principles)

### I. 페르소나 중심 설계 (Persona-Driven Design)

모든 기능과 사용자 경험은 3개의 핵심 페르소나를 기반으로 설계되어야 한다.

**필수 요구사항:**
- **장애인 가족 (서비스 이용자)**: 긴급돌봄, 방과후 홈티, 상담, 맞춤형 여행 등 즉각적 서비스 접근
- **B2B 고객 (협력 기관)**: 전문인력 파견, 서비스 제안, 파트너십 문의 경로 명확화
- **후원 파트너**: 후원/기부 정보, 임팩트 스토리, 협력 기회 제공

**비타협적 규칙:**
- 각 페르소나별 전용 진입점과 맞춤형 콘텐츠 제공 필수
- 페르소나 간 혼동을 초래하는 UI/UX 금지
- 모든 신규 기능은 대상 페르소나를 명시해야 함

**근거:**
DFP Connect는 정보 게시판이 아닌 '경험 연결'의 디지털 허브입니다. 각 방문자의 니즈에 맞는 최적화된 경험 제공이 프로젝트의 핵심 가치입니다.

### II. 접근성 우선 (Accessibility First)

웹 접근성 표준(WCAG 2.1 AA 이상)을 준수하여 모든 사용자가 차별 없이 서비스를 이용할 수 있어야 한다.

**필수 요구사항:**
- 시맨틱 HTML 사용 및 스크린 리더 호환성
- 키보드 내비게이션 완벽 지원
- 충분한 색상 대비 (최소 4.5:1)
- 대체 텍스트 및 ARIA 레이블 제공
- 반응형 디자인으로 모든 디바이스 지원

**비타협적 규칙:**
- 접근성 테스트를 통과하지 못한 코드는 배포 불가
- 장애인 사용자 피드백 반영 프로세스 필수
- 접근성 저해 요소(자동 재생 비디오, 깜빡임 등) 금지

**근거:**
장애인 가족을 위한 플랫폼으로서, 접근성은 선택이 아닌 필수입니다. 모든 사용자의 디지털 권리를 보장해야 합니다.

### III. 보안 및 개인정보 보호 (Security & Privacy)

민감한 개인정보와 서비스 요청 데이터를 최고 수준으로 보호해야 한다.

**필수 요구사항:**
- 개인정보 최소 수집 원칙
- 데이터 암호화 (전송 중: HTTPS, 저장 시: AES-256)
- 인증/인가: Clerk 기반 보안 체계
- 정기적인 보안 감사 및 취약점 스캔
- GDPR, 개인정보보호법 준수

**비타협적 규칙:**
- 인증되지 않은 사용자의 민감 정보 접근 금지
- 비밀번호, API 키 등 자격증명 코드 저장소 커밋 절대 금지
- SQL Injection, XSS 등 OWASP Top 10 취약점 사전 차단

**근거:**
긴급돌봄, 상담 등 민감한 서비스를 다루므로 사용자 신뢰가 최우선입니다. 보안 사고는 조직의 존립을 위협할 수 있습니다.

### IV. 성능 및 안정성 (Performance & Reliability)

긴급 상황 대응 서비스 특성상 높은 가용성과 빠른 응답 속도가 필수적이다.

**필수 요구사항:**
- 초기 로딩 시간 3초 이내 (LCP)
- 모바일 환경 최적화 (First Input Delay < 100ms)
- 99.9% 가용성 목표 (연간 다운타임 < 8.76시간)
- 에러 모니터링 및 자동 알림 체계
- CDN 활용 및 이미지 최적화

**비타협적 규칙:**
- 성능 저하를 유발하는 코드는 리뷰 단계에서 반려
- 프로덕션 배포 전 성능 테스트 필수
- 긴급돌봄 요청 경로는 최우선 최적화 대상

**근거:**
"보호자가 입원했는데, 오늘 당장 아이를 맡길 곳이 필요해요" - 이러한 긴급 상황에서 느린 웹사이트는 실질적인 피해를 초래합니다.

### V. 테스트 기반 개발 (Test-Driven Development)

코드 품질 보장 및 회귀 버그 방지를 위해 체계적인 테스트가 필수적이다.

**필수 요구사항:**
- 단위 테스트: 핵심 비즈니스 로직 커버리지 80% 이상
- 통합 테스트: 페르소나별 주요 사용자 플로우
- E2E 테스트: 긴급돌봄 요청, 로그인, 회원가입 등 크리티컬 경로
- CI/CD 파이프라인에 자동 테스트 통합

**비타협적 규칙:**
- 테스트가 실패하면 배포 차단
- 새로운 기능은 반드시 테스트 코드와 함께 제출
- 프로덕션 버그 발생 시 재발 방지 테스트 추가 필수

**근거:**
사용자의 안전과 서비스 신뢰도가 직결된 프로젝트이므로, 예측 가능하고 안정적인 코드베이스 유지가 필수입니다.

### VI. 한국어 우선 및 현지화 (Korean-First Localization)

주 사용자가 한국의 장애인 가족이므로 한국어 경험이 최우선이다.

**필수 요구사항:**
- 모든 UI/UX 텍스트는 한국어 기본 제공
- 날짜, 시간, 통화 등 한국 표준 준수
- 한국 사용자 습관에 맞는 UX 패턴 적용
- Clerk 등 외부 서비스도 한국어 설정

**비타협적 규칙:**
- 기계 번역 의존 금지 (네이티브 한국어 검수 필수)
- 핵심 서비스 경로에 영어 전용 화면 존재 금지

**근거:**
긴급 상황에서 언어 장벽은 치명적입니다. 명확하고 친근한 한국어로 소통해야 합니다.

## 기술 제약사항 (Technical Constraints)

### 기술 스택 표준

**프론트엔드:**
- Framework: Next.js 16+ (App Router)
- Language: TypeScript 5.9+
- Styling: Tailwind CSS 3.0+
- UI Components: shadcn/ui

**인증:**
- Clerk (소셜 로그인, 세션 관리 포함)

**배포:**
- Platform: Google Cloud Platform (Cloud Run)
- Region: asia-northeast3 (서울)
- CI/CD: GitHub Actions + Cloud Build

**근거:**
검증된 기술 스택을 사용하여 개발 생산성과 유지보수성을 확보합니다.

### 의존성 관리

- 패키지 업데이트 전 보안 취약점 스캔 필수
- 메이저 버전 업그레이드는 테스트 계획 수립 후 진행
- 사용하지 않는 의존성 정기 정리

## 개발 워크플로우 (Development Workflow)

### 브랜치 전략

- `main`: 프로덕션 배포 브랜치 (보호됨)
- `feature/*`: 기능 개발 브랜치
- `fix/*`: 버그 수정 브랜치
- `hotfix/*`: 긴급 수정 브랜치

### 코드 리뷰 정책

- 모든 PR은 최소 1명의 리뷰 승인 필수
- 리뷰 체크리스트:
  - [ ] 헌장 원칙 준수 (페르소나, 접근성, 보안, 성능)
  - [ ] 테스트 코드 포함 및 통과
  - [ ] TypeScript 타입 안정성
  - [ ] 한국어 텍스트 품질
  - [ ] 문서 업데이트 (필요 시)

### 배포 프로세스

1. PR 병합 → GitHub Actions 자동 트리거
2. 빌드 및 테스트 실행
3. Cloud Build → Docker 이미지 생성
4. Cloud Run 자동 배포 (main 브랜치)
5. Slack/이메일 배포 알림

**롤백 절차:**
- 프로덕션 이슈 발생 시 이전 버전으로 즉시 롤백
- 이슈 수정 후 재배포

## 품질 관리 (Quality Assurance)

### 코드 품질 도구

- **ESLint**: JavaScript/TypeScript 정적 분석
- **ShellCheck**: Shell 스크립트 검증
- **Markdownlint**: 문서 품질 검증
- **SpecKit**: 통합 검증 프레임워크

### 정기 점검

- 주간: 보안 취약점 스캔
- 월간: 접근성 감사
- 분기: 성능 벤치마크
- 연간: 전체 아키텍처 리뷰

## 거버넌스 (Governance)

### 헌장 우선 원칙

이 헌장은 모든 개발 프랙티스, 의사결정, 코드 리뷰 기준보다 우선합니다.

헌장과 충돌하는 코드나 프로세스는 즉시 수정되어야 합니다.

### 헌장 수정 절차

1. **제안**: 수정 제안서 작성 (배경, 변경 내용, 영향 분석)
2. **검토**: 팀 전체 검토 및 토론
3. **승인**: 만장일치 또는 80% 이상 동의
4. **마이그레이션 계획**: 기존 코드 영향 분석 및 전환 계획 수립
5. **문서화**: 변경 이력 및 버전 업데이트

### 버전 관리 정책

- **MAJOR**: 핵심 원칙 제거/재정의 (후방 호환성 없음)
- **MINOR**: 새로운 원칙/섹션 추가
- **PATCH**: 문구 수정, 오타 수정, 명확화

### 준수 검증

- 모든 PR/리뷰에서 헌장 준수 검증 필수
- 복잡도 증가는 명확한 근거와 함께 문서화
- 헌장 위반 시 즉시 시정 조치
